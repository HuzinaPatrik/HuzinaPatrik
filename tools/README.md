# Profile asset generator

Every image in the profile README is an SVG generated by `build.mjs`. Nothing is loaded from a
third-party service, so nothing can be rate-limited or go offline.

```bash
cd tools
npm install
npm run build      # rewrites ../assets and the generated blocks of ../README.md
npm run preview    # renders ../README.md through GitHub's markdown API into ../.preview/*.html (needs gh)
```

## Changing what the profile says

Edit `content.mjs` and run the build: the name and role line, the three disciplines, every card
(title, one-line blurb, chips, [Lucide](https://lucide.dev) icon name) and both colour themes live
there. The build warns when two cards that share a row need different heights, or when a title
does not fit.

## How it renders on GitHub

- Text is converted to outlines, because an SVG shown through `<img>` cannot load web fonts. The
  type is identical on every OS; the accessible text lives in each image's `alt` and in the
  plain-text `<details>` block of the README.
- Dark and light variants are swapped with `<picture>`, which follows the viewer's GitHub theme.
  Image URLs are absolute (`assetBase` in `content.mjs`), because the GitHub mobile apps do not
  resolve relative paths inside `<picture>`.
- Cards are 400 px wide inline images: two per row on a desktop (the profile README is 846 px
  wide), one per row on a phone.
- Be careful with `<picture>` sources that combine a width with `prefers-color-scheme`. For viewers
  who force a theme, GitHub's `themed-picture` script replaces the whole media attribute of every
  colour-scheme source with "always match" or "not all", which drops the width. The common
  `(max-width: 600px) and (prefers-color-scheme: dark)` pattern therefore shows the phone image on
  desktops. The hero avoids this by making dark the `<img>` fallback and listing the desktop-light
  source first (see the comment above `picture()` in `build.mjs`); headings and the footer switch
  layout with a width query inside the SVG instead.
- No `prefers-color-scheme` inside the SVGs: Safari ignores it for images.
- Motion is limited to the hero loop and one power-on blink per card, and is switched off under
  `prefers-reduced-motion`. The resting state of every animation is the finished frame.
